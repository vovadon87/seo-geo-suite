# seo-geo-suite

Набор навыков и агентов для Claude, который помогает продвигать сайт в поиске (Яндекс, Google) и в ответах нейросетей. Подходит для любого сайта и любой ниши: ничего не привязано к конкретной компании.

## Для чего он нужен

Вы пишете Claude обычным языком: «проверь сайт», «собери семантику», «напиши текст для страницы», «сделай отчёт за месяц». Набор сам выбирает нужный инструмент, проверяет сайт по фактам и выдаёт список проблем с приоритетами: что исправить сначала, почему это важно и как проверить результат.

Набор ничего не меняет на сайте сам и не обещает рост позиций. Он находит проблемы, готовит правки и честно пишет, что не удалось проверить.

## Из чего состоит

Папка `.claude/skills/` — навыки:

| Навык | Что делает |
|---|---|
| `seo-geo` | Главный: понимает задачу, заводит профиль нового сайта, передаёт работу нужному навыку, собирает полный аудит |
| `tech-audit` | Технический аудит: доступность сайта, редиректы, robots и sitemap, дубли, заголовки, разметка, доступ для ИИ-ботов, сравнение страницы до и после JavaScript |
| `speed-audit` | Скорость: вес страницы, Core Web Vitals, картинки, сторонние скрипты |
| `semantics` | Поисковые запросы: сбор, группировка по смыслу, карта «запрос → страница» |
| `content-geo` | Тексты и страницы для поиска и для ответов нейросетей, проверка фактов и качества |
| `local-seo` | Региональное SEO: адреса, телефоны, единые данные о компании на сайте и в картах |
| `seo-report` | Отчёт за период: сравнение месяцев по выгрузкам Вебмастера и Search Console, задачи на следующий период |
| `_shared` | Общие правила: приоритеты P0–P3, формат находки, обязательный раздел «что не проверено» |

Папка `.claude/agents/` — помощники, которые работают параллельно:

- `seo-tech-auditor` — технический аудит;
- `seo-speed-auditor` — аудит скорости;
- `seo-content-auditor` — аудит содержания страниц;
- `seo-geo-writer` — пишет тексты по правилам набора.

Остальное: `evals/` — 36 сценариев для проверки работы набора, `sites/` — сюда складываются профили ваших сайтов.

## Как это работает

1. Вы называете сайт и задачу. Если сайт новый, набор изучает нишу и создаёт его профиль, а спорные факты выносит в вопросы вам.
2. Скрипты на Python (только стандартная библиотека, для проверки JavaScript нужен Playwright) проверяют сайт и собирают данные.
3. Claude разбирает результат, отбрасывает ложные срабатывания и пишет отчёт.
4. При запросе «полный аудит» три агента-аудитора работают одновременно, а их находки объединяются в один список без повторов.

## Установка

Скопируйте папки `.claude/skills` и `.claude/agents` в `~/.claude/` (для всех проектов) или оставьте в репозитории (для одного проекта). Python 3.9+. Скрипты запускаются из своих папок `scripts/`.

## Что проверено, а что нет

Проверено: тесты скриптов проходят; технический обход, проверка скорости и объединение находок отработали на живом сайте.

Не проверено: выгрузка из Search Console и Вебмастера по API (нужны ваши токены, тесты шли на имитации), данные PSI и CrUX (нужны ключи), работа агентов на разных сайтах. Группировка запросов и определение интента — черновик для проверки человеком. Проверка JavaScript из облака не показывает регион и статус индексации.
# seo-geo-suite

Набор навыков для SEO и GEO (видимость в поиске и в ответах ИИ) любого сайта и любой ниши. Вариант 2 из обсуждения: роутер + независимые модули, нишевых знаний в навыках нет, профиль сайта создаётся при подключении (onboard).

## Что проверено
- `tech-audit/scripts/run_tests.py`: 10 тестов на локальном сайте с заведомыми проблемами (дубли, битые ссылки, цепочки редиректов, noindex в sitemap, сироты, глубина, мягкая 404, шаблонная разметка, robots).
- `tech-audit/scripts/run_render_tests.py`: 7 тестов `render_check.py` (SPA с контентом, ссылками, мета и разметкой только после JS; статичная страница без находок; noindex, снятый JS).
- `seo-report/scripts/run_api_tests.py`: 8 тестов `api_fetch.py` на локальном имитаторе GSC и Вебмастера (структура запросов и ответов по документации, пагинация, ошибки, совместимость CSV с `period_compare.py`).
- `seo-geo/scripts/run_tests.py`: 8 тестов `merge_findings.py` (чтение четырёх форматов находок, объединение дублей, сортировка, вопросы владельцу).
- Агенты-аудиторы на реальном сайте **не запускались**: это описания процедур, их работа зависит от окружения (доступность субагентов, Chromium, ключи).
- `speed-audit/scripts/run_tests.py`: 7 тестов; `page_weight.py` и `lighthouse_run.py` прошли сквозной запуск в Chromium и Lighthouse 12 на локальном «тяжёлом» сайте.
- Контрольный прогон `site_crawl.py` на публичном сайте (gzip, редиректы, разбор HTML без кавычек в атрибутах).
- Фаза 2: `semantics` 13 тестов, `content-geo` 13, `local-seo` 9, `seo-report` 13 (синтетические данные; кластеризатор проверен на нише «ремонт квартир»). Кластеры и интент — черновик для проверки человеком, частотность Wordstat скрипты не выдумывают.
- **Не проверено вживую:** вызовы GSC API и API Вебмастера (нет токенов); а также вызовы PSI и CrUX API (нужен ключ Google; разбор ответов проверен на синтетических данных по документации). Первый реальный запуск с ключом — контрольная точка.

## Полный аудит агентами
Агенты лежат в `agents/` (положить в `.claude/agents/` репозитория или `~/.claude/agents/`). Главный сеанс запускает трёх аудиторов параллельно, сводит находки `seo-geo/scripts/merge_findings.py` и пишет итог по `seo-geo/templates/full-audit-report.md`. Порядок и контракт ответа — `seo-geo/references/full-audit.md`. Стоит больше токенов, чем один модуль; для малых сайтов запускайте модули по очереди.

## Установка

**Как навыки аккаунта** (чтобы вызывались сами): сохранить карточки SKILL.md всех семи навыков (`seo-geo`, `tech-audit`, `speed-audit`, `semantics`, `content-geo`, `local-seo`, `seo-report`). Карточка сохраняет только текст SKILL.md.

**Скрипты и справочники** живут в репозитории. Положить папки в `.claude/skills/<имя>/` репозитория `etiketka-claude` (или в `~/.claude/skills/<имя>/` на основной машине), а `_shared/` и `evals/` — рядом. Тогда SKILL.md находит `scripts/` рядом с собой. В облачной сессии на репозитории они подтянутся автоматически.

Зависимости: Python 3.9+ (скрипты tech-audit — стандартная библиотека); для `page_weight.py` — `pip install playwright` и Chromium; для `lighthouse_run.py` — Node.js и `npm i -g lighthouse`.

Ключи (по желанию, у владельца): `PSI_API_KEY`, `CRUX_API_KEY` — Google Cloud Console, включить PageSpeed Insights API и Chrome UX Report API. В репозиторий не коммитить.

## Миграция с audit-seo-geo
- Все режимы `audit-seo-geo` покрыты модулями набора: `audit` → tech-audit, `onboard` → seo-geo, `semantics` → semantics, `content`/`geo`/`page` → content-geo, `local` → local-seo, `report` → seo-report. После проверки набора старый навык можно убрать из роутинга; сам репозиторий не трогать до решения владельца.
- Старые `crawl.py` и `check_page.py` заменены универсальным `site_crawl.py` (без нишевых привязок).
- Профиль `sites/etiketka/` переносится как есть; формат совместим.
- Агент `seo-geo-writer` обобщает `etiketka-seo-geo-writer`; нишевый агент и `etiketka-seo-geo-articles` не затронуты.
- Скрипты `wordstat_io.py`, `quality_checks.py`, `md_to_html.py`, `build_pdf.py` скопированы из репозитория без изменений.

## Ограничения
- `site_crawl.py` не исполняет JavaScript (для этого есть `render_check.py`: 10 страниц по умолчанию, из места запуска), не знает статус индексации и не читает логи; охват ограничен `--max-pages`.
- Лабораторная скорость измеряется из места запуска; для аудитории в другом регионе опираться на поле (CrUX, Метрика).
- Список ИИ-ботов в `robots_check.py` нужно периодически сверять с документацией владельцев ботов.
