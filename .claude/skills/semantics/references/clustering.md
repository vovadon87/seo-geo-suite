# Кластеризация и приоритизация запросов

## Нормализация и очистка
1. Дедупликация по нормализованной форме (`wordstat_io.py`, `cluster_phrases.py`). При дублях берётся наибольшая известная частотность; «нет данных» не затирает число.
2. Исключать из целей: дубли; другой продукт или другое значение слова; нецелевые интенты (скачать, вакансии, реферат); продукт, которого компания не делает; несоответствие аудитории (B2C для B2B и наоборот — оценить отдельно, не выбрасывать автоматически).
3. Не исключать фразу только из-за синонима, если владелец подтвердил: это один и тот же продукт (решение хранится в профиле).
4. Исключённое не удалять: лист «Нецелевые» с причиной и кандидатом в минус-слова.

## Кластер
Группа фраз с одним интентом и одной задачей пользователя, закрываемая одним разделом или одной страницей. Объединять: общий объект (вид продукта, вариант, условие) + совместимый интент. Не объединять: разные объекты («ремонт квартир» и «ремонт офисов»), разные известные интенты (заказать и как сделать самому).
Для каждого кластера: название, главная задача пользователя, главная фраза (наибольшая подтверждённая частотность), целевой URL.

## `cluster_phrases.py`: что делает и где ошибается
Делает: нормализация, дедупликация, интент по маркерам (transactional / info_commercial / commercial_investigation / informational / navigational / unknown), нецелевые маркеры, кластеры по пересечению основ слов (порог Жаккара 0,6) с запретом объединять разные известные интенты, синонимы «цена/стоимость/прайс» как одна основа, главная фраза, суммы частотностей, авто-балл.
Ошибается: слова-омонимы и разные объекты с общими словами; редкие словоформы; фразы с одним словом; смешанные интенты. Порог ниже — крупнее кластеры (больше смешивания), выше — мельче (больше дублей). Результат — черновик для проверки человеком, не итоговая карта.

## Оценка возможности кластера (Opportunity Score, 0–100)
Внутренняя модель для сортировки работ, не алгоритм поисковика. Веса фиксируются для воспроизводимости; при необходимости меняются в `weights.json` и записываются в профиль.

| Фактор | Вес | Как считается | Кто считает |
|---|---:|---|---|
| Релевантность продукту | 25 | 0 нет / 12 часть / 25 прямое совпадение: доля фраз кластера со словами из `--relevant` ≥30% → часть, ≥80% → прямое | скрипт, проверить человеку |
| Подтверждённый спрос (макс. широкая частотность) | 20 | нет данных 0; ≤10 → 5; 10–100 → 10; 100–1000 → 15; >1000 → 20 | скрипт |
| Коммерческий интент | 20 | transactional 20; info_commercial и commercial_investigation 15; informational и unknown 5; navigational 0 | скрипт, по выдаче уточнить |
| Потенциал заявки | 15 | 0–15 по аудитории и цене ошибки покупателя | **человек** |
| Охват страницей | 10 | 10 не раскрыт / 5 частично / 0 раскрыт | **человек** (по сопоставлению с сайтом) |
| Риск каннибализации | 10 | 10 нет / 5 управляемый ссылкой / 0 высокий | **человек** |

Скрипт заполняет три фактора (максимум 65, если задан `--relevant`; без него — 40) и оставляет три колонки пустыми. Итог считать только после заполнения; незаполненный балл называть «авто-балл», а не итогом. Конкурентность учитывать только по реальным данным выдачи — как заметку, не как слагаемое. Балл не попадает в тексты и обещания клиенту.

## Выход
`semantic-map` (`templates/semantic-map.md`): кластер → интент → фразы с частотностью и источником → задача пользователя → целевой URL → балл → решение (раскрыть в блоке страницы / отдельная страница / не использовать). Суммы частотностей — с оговоркой о пересечении.
