# ЭПОС Яндекса: проверка текста по четырём аспектам

Источник методики: справка Яндекс Вебмастера об ЭПОС (проверять актуальность при обновлении навыка). ЭПОС — рамка оценки качества контента: **Э**кспертность, **П**олезность, **О**ригинальность, **С**одержательность. Это критерии оценки, а не чек-лист ранжирования; прохождение позиций не обещает.
Результат проверки — таблица: аспект → вердикт (проходит / требует доработки) → доказательства (цитаты из текста) → что исправлено.

## Э — Экспертность
Опора на реальные сведения, прослеживаемые до источника (реестр fact check). Что считать конкретикой, зависит от ниши (по профилю): параметры продукта, материалы и их поведение, технологии и ограничения, требования к исходным данным клиента, регламенты, сроки и этапы, нормативные требования.
Проверка: каждое техническое утверждение — VERIFIED или GENERAL VERIFIED; факты компании — только со статусом ПВ/ОС. NEEDS VERIFICATION в публикуемый текст не попадает. Для чувствительных тем: автор и его квалификация указаны, ссылки на первичные источники.

## П — Полезность
Каждый раздел решает конкретную задачу читателя. После раздела ответить:
1. На какой вопрос пользователя он ответил?
2. Какое решение читатель сможет принять?
3. Есть ли практический результат (критерий выбора, порядок действий, таблица)?
4. Можно ли сократить без потери информации? Если да — сократить.
Абзац, не прошедший вопросы 1–3, удаляется или переписывается. Вводные абзацы без информации удалять.

## О — Оригинальность
Смысловая, не лексическая. Текст конкурента, переписанный своими словами, оригинальным не считается.
Источники: производственная или практическая экспертиза (подтверждённая); сравнения «вариант × условие» с выводами; типичные ошибки заказчиков; критерии выбора, которых нет у конкурентов (`information-gain.md`); подтверждённые примеры с параметрами.
Проверка: сопоставить план текста с анализом конкурентов; в итоговом отчёте перечислить содержательные элементы, которых нет у проанализированных.

## С — Содержательность
Максимально полное раскрытие целевого интента при высокой плотности пользы.
- Не наращивать объём ради символов; длина определяется интентом.
- Один смысл — один раздел; не повторять мысль под разными заголовками.
- Не смешивать самостоятельные интенты без необходимости; для отдельного интента — отдельная страница (режим `cluster`).
- Проверка покрытия — Semantic Coverage Matrix (по смыслу).

## Порядок
1. `scripts/quality_checks.py` (механическая часть).
2. Четыре аспекта вручную с цитатами.
3. Провалы исправить и повторить проверку (до 3 циклов; затем зафиксировать ограничение и вопрос владельцу).
