# onboard: подключение сайта любой ниши

Цель: за одну сессию получить черновик профиля, на котором можно безопасно работать, и список вопросов владельцу. Заготовленных пакетов ниш нет: всё выводится из сайта и выдачи.

## Шаг 1. Обход сайта
`python tech-audit/scripts/site_crawl.py <url> --max-pages 60 --out sites/<имя>/crawl-<дата>`
Взять из `crawl.json`: структуру разделов, шаблоны страниц, контакты, адреса, юрлицо, формулировки сроков и условий, формы, счётчики, CMS (по признакам), состояние технической части (кратко, подробности — в `tech-audit`).

## Шаг 2. Определение ниши
Заполнить по тому, что видно на сайте. Что не видно — `Н`, в список вопросов.
- Что продают (продукты/услуги), для кого, в каком сегменте цены (если указано).
- Модель: заявки/звонки; интернет-магазин; контент/реклама; локальная услуга с адресом; SaaS/подписка; маркетплейс/каталог.
- Покупатель: B2B или B2C; лицо, принимающее решение; цикл покупки (импульс / сравнение / тендер).
- География: где офис, производство, точки выдачи, зона доставки или выезда.
- Чувствительность темы: здоровье, финансы, право, безопасность детей и подобное → строгий режим: только подтверждённые утверждения, экспертное авторство, никаких обещаний результата, оговорки по закону. Иначе обычный режим.

## Шаг 3. Выдача и конкуренты
Для 5–8 запросов, выведенных из сайта (продукт, задача покупателя, сравнение, цена/срок, регион, бренд):
- Тип страниц в топе: коммерческие, статьи, каталоги, агрегаторы, карточки на картах.
- Доминирующий интент и признаки выдачи (карты, быстрые ответы, видео, маркетплейсы).
- 3–5 конкурентов: домен, чем отличается предложение, какие страницы закрывают спрос. Только наблюдаемые факты, без догадок о ценах и объёмах.
Если инструмента поиска нет, не придумывать выдачу: записать «выдача не изучалась» и предложить владельцу назвать конкурентов.

## Шаг 4. Направления семантики
Список направлений с пометкой «предварительно»: виды продукта; варианты/материалы (только из `site-context.md`); отрасли и задачи покупателя; условия применения; тираж, цена, срок; регионы. Частотность не выдумывать; без данных Wordstat/GSC числа не указывать.

## Шаг 5. Ограничения
Что нельзя утверждать без подтверждения владельца: цены, скидки, клиенты, сроки, сертификаты, оборудование, гарантии, результаты. Для строгого режима добавить отраслевые запреты.

## Шаг 6. Вопросы владельцу (один сжатый список)
- Идентичность: бренд, юрлицо, адреса и роль каждой точки (офис, производство, выдача, склад).
- Ассортимент: что реально продаётся, а чего нет; допустимые варианты.
- Условия: минимальный заказ, сроки, цены, что можно писать публично.
- География: где работаете, куда доставляете.
- Доступы: Вебмастер, GSC, Метрика, CMS, CRM.
- Цели: что считать квалифицированной заявкой.

## Шаг 7. Запись профиля
Создать `sites/<имя>/` из `templates/site-context.md` и `templates/profile.md`. Статусы фактов: **ПВ** — подтверждено владельцем; **ОС** — опубликовано на сайте; **Г** — гипотеза; **Н** — неизвестно. Профиль — черновик, пока владелец не ответит на вопросы.

## Шаг 8 (по желанию, с согласия владельца): заметки о нише
Если ниша встретится снова, можно сохранить обезличенные методические наблюдения (типичные интенты, паттерны выдачи, риски утверждений) в `niche-notes/<слаг>.md`. Фактов конкретной компании там быть не должно. Заметки — подсказка для следующего onboard, а не источник утверждений для сайта.

## Что не делать
- Не переносить факты другого профиля.
- Не заполнять «разумными догадками» ассортимент, цены, сроки, регионы.
- Не делать вывод о нише по одному заголовку; проверить 3–5 страниц.
