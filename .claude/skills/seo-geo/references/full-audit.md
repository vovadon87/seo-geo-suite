# Полный аудит: параллельный запуск аудиторов

Когда нужен: «проведи полный SEO-аудит сайта». Для узкой задачи (только техника, только скорость) запускать один модуль, а не всех.

## Роли
- Главный агент (основной сеанс): определяет профиль, запускает аудиторов, сводит результаты, пишет итог. Субагенты других субагентов не запускают, поэтому оркестрация только здесь.
- `seo-tech-auditor`: `tech-audit` → `audit-out/tech/`.
- `seo-speed-auditor`: `speed-audit` → `audit-out/speed/`.
- `seo-content-auditor`: `content-geo` (audit), `semantics`, `local-seo` → `audit-out/content/`, `audit-out/local/`.
Все аудиторы только читают сайт; пишут лишь в свою подпапку `audit-out/`.

## Порядок
1. **Цель и охват.** URL, лимит страниц, регион аудитории, ключевые страницы, выгрузки запросов, ключи PSI/CrUX. Чего нет — записать в «не проверено».
2. **Профиль.** Есть профиль `sites/<имя>/` — прочитать; нет — выполнить onboard (обход 60 страниц, ниша), профиль считать черновиком. Это делает главный агент до запуска аудиторов: им нужны ниша и ключевые страницы.
3. **Запуск параллельно:** три вызова Agent в одном сообщении. Бриф каждому: URL, лимиты, ключевые страницы, регион, пути к профилю и выгрузкам, общая папка `audit-out/`, «верни сводку не больше 25 строк». Ключи API не передавать в бриф: аудиторы берут их из окружения.
4. **Сведение:** `python scripts/merge_findings.py audit-out --out audit-out` → `merged-findings.md` и `.csv` (находки по приоритетам, объединённые дубли, вопросы владельцу).
5. **Итог** по `templates/full-audit-report.md`: охват каждого аудитора, сводка 3–5 выводов, противоречия фактов владельцу, находки P0–P3 (из сводки, с проверкой выборочно: 2–3 самых важных P0/P1 открыть самому), план 14/30/90 дней, не проверено и как проверить.
6. **Не решать за владельца:** противоречия фактов, ИИ-боты, региональные страницы, публикацию.

## Стоимость и когда не запускать
Три аудитора параллельно тратят больше токенов, чем один модуль, и дают выигрыш во времени на больших сайтах. Для сайта до ~30 страниц хватит последовательного запуска модулей. Если агенты недоступны в окружении, выполнить те же шаги по порядку самому.

## Контракт ответа аудитора
Охват; число находок P0–P3; топ-5 с URL; пути к файлам; не проверено и как проверить; вопросы владельцу. Находки — в `findings.json` (id, priority, problem, urls, evidence, fix, recheck, confidence, ask_owner, module), чтобы сводка не зависела от пересказа.

## Проверка результата сводки
Противоречия между аудиторами (например, контент требует индексации страницы, техника нашла на ней noindex) вынести отдельным пунктом, не усреднять.
