# Критерии технического аудита

Формат находки: **URL → доказательство → последствие → исправление → повторная проверка → P0–P3 / уверенность / трудоёмкость / зависимости / критерий готовности.**
ID — идентификаторы находок `site_crawl.py`.

## 1. Адреса и доступность (D1–D3)
- Один канонический вариант (протокол + www/без www), остальные — 301. Проверка: `curl -I` по четырём вариантам.
- Редирект постоянный (301/308), не временный. Цепочек ≤1 перехода.
- Доступность (200) ≠ индексация; смотреть Вебмастер («Страницы в поиске») и GSC («Проверка URL»).
- `D1` P0: несколько вариантов отдают 200 — дубли всего сайта.

## 2. robots.txt (R1–R4)
- Закрыть служебное (админка, корзина, поиск по сайту, страницы благодарности, параметры); CSS/JS/картинки не закрывать.
- `Clean-param` для Яндекса при utm и других метках; строка `Sitemap:`.
- `R1` P0: `Disallow: /` для всех.
- Матрица ИИ-ботов (`robots_check.py`): различать поиск (OAI-SearchBot, Claude-SearchBot, PerplexityBot, YandexBot), загрузку по запросу пользователя (ChatGPT-User, Claude-User, Perplexity-User) и обучение (GPTBot, ClaudeBot, Google-Extended, CCBot). Решение «открыть/закрыть» — бизнесу, а не шаблону. Закрытие обучающих ботов не закрывает поиск.
- Список ботов устарел быстро: сверять с документацией владельцев ботов.

## 3. Sitemap (S1–S5)
- Только канонические URL со статусом 200, без noindex. Крупные сайты — sitemap index.
- После смены домена/протокола проверить `<loc>`.
- Страницы-сироты (в sitemap, без внутренних ссылок) и страницы без sitemap — не ошибка сами по себе; решить по ценности страницы.

## 4. Коды ответа (P-4xx, P-5xx, P-CHAIN, P-RLINK, P-SOFT404)
- Внутренние ссылки ведут на 200; битых 0; несуществующий адрес отдаёт 404 (не 200 с оформлением главной).
- 5xx — P0 при повторяемости; единичный сбой перепроверить.

## 5. Title, description, заголовки (M1–M7)
- Title уникален, главный запрос ближе к началу, бренд в конце; ~60–70 символов — ориентир по обрезке сниппета, не требование.
- Description уникален и продаёт клик (оффер, условие, действие); ~150–160 символов — ориентир.
- Один H1, согласован с title и намерением страницы; H2 по смысловым блокам.
- Подмена заголовков скриптом (по UTM, региону) не должна менять версию без параметров.

## 6. Canonical и индексация (C1–C5)
- Self-canonical на канонический URL; без параметров меток.
- `C4` не всегда ошибка: canonical на другую страницу допустим для дублей. Проверить намерение.
- noindex — только служебные страницы. Страница с noindex в sitemap — противоречие (`S3`).
- Почти одинаковые страницы: развести по намерению или склеить canonical/редиректом.

## 7. Мобильная версия и язык (X1–X3)
- viewport; нет горизонтальной прокрутки на 320–390 px; крупные цели нажатия (≥44 px); `tel:` у телефона.
- `lang` у `<html>`; hreflang со ссылкой на себя и обратными ссылками.

## 8. Структура и ссылки (T1, T2)
- Ключевая страница достижима с главной ≤3 кликов и имеет ≥2 внутренних ссылки с осмысленным анкором.
- Мало текста (T1) — не ошибка; проверить, закрывает ли страница намерение.

## 9. Контент в HTML и после JavaScript
- Основной текст и ссылки — в исходном HTML. Скрипт-подстановки — поверх базового текста.
- Контент в квизах, табах без разметки и попапах роботам может быть не виден: ключевые условия держать в тексте.
- Скрипт `site_crawl.py` не исполняет JS. Для SPA и сайтов с отложенной отрисовкой сравнить «исходный HTML» и DOM в браузере.

## 10. Изображения (I1–I3)
- Содержательный alt (декоративные — `alt=""`); `width/height` или aspect-ratio; битых 0.
- Форматы, вес, lazy, LCP-картинка — в `speed-audit`.

## 11. Безопасность контента, сжатие, ответ (H1, V1–V3)
- Смешанный контент (http на https) — P1.
- HTML, CSS, JS — со сжатием (br/gzip).
- Время до первого байта >1.5 с из места запуска — повод проверить, не вывод. Подтверждать полевым TTFB и `speed-audit`.

## 12. Структурированные данные (L1, L2)
- Валидный JSON-LD; данные совпадают с видимым текстом страницы; нет шаблонных значений («[Название]», «ваш-домен»).
- Подходят по смыслу: Organization/LocalBusiness (реальные адреса и телефоны), BreadcrumbList, Product/Service, Article, FAQPage (если вопросы и ответы видны на странице).
- Не добавлять AggregateRating, Review, цены Offer без реальных данных; расширенный сниппет не обещать.
- Проверка во внешних сервисах: Rich Results Test, validator.schema.org, раздел структурированных данных Яндекс Вебмастера.

## Где вносить правки (по CMS)
| CMS | Title, Description, canonical, noindex | robots.txt, sitemap | Разметка, preload | Особенности |
|---|---|---|---|---|
| Tilda | Настройки страницы → SEO | Настройки сайта → SEO/Домен | Настройки сайта → Дополнительно → HEAD; блоки T123 | sitemap пересобирается сама, после смены зеркала проверить протокол; оптимизатор картинок `/-/resize/…/-/format/webp/` |
| WordPress | плагин SEO (Yoast, Rank Math, SEOPress) или тема | физический файл или плагин | плагин/тема, `functions.php` | пагинация и метки порождают дубли; кэш-плагин влияет на TTFB |
| 1С-Битрикс | Свойства раздела/элемента, шаблон компонента | `robots.txt` в корне, модуль SEO | шаблон сайта | параметры сортировки и фильтра создают дубли |
| Shopify / Webflow / Wix | настройки страницы | управляются платформой | кастомный код в head | часть технических параметров недоступна — документировать ограничение |
| Самописный сайт | шаблон / бэкенд | файлы в корне | шаблон | согласовать правки с разработчиком, дать готовый diff |

Перед заменой блока или шаблона — копия исходника. После публикации проверять живой адрес, не редактор.

## Отчёт и уверенность
- Уверенность «высокая»: воспроизводится на нескольких URL, понятен механизм.
- «Средняя»: гипотеза на основании паттерна, нужна проверка в Вебмастере/GSC.
- «Низкая»: единичный случай или данные из ограниченной выборки.
